# RepoRove 使用指南

适用版本：0.6.1，Android 10 及以上。

## 安装与更新

在 [Releases](https://github.com/zurrll/RepoRove/releases) 下载 APK，用系统安装器安装。如果系统要求，允许当前浏览器或文件管理器安装应用。每版同时提供 SHA-256 校验文件。

预览包采用同一开发签名，可以覆盖同签名旧版；安装前无需卸载。卸载会丢失 App 内稍后看、设置、阅读缓存和离线仓库；系统下载文件另行管理。开发签名用于当前预览渠道，不代表已满足应用商店发布要求。

## 发现与搜索

“为你”根据自己填写的兴趣找项目；打开兴趣调整可以勾选建议主题，也能输入例如 `python` 的主题。是否参考已 Star 项目由你选择。推荐卡片的反馈会影响后续候选，可以撤销或在设置中恢复。

“主题”和“合集”的目录来自 GitHub Explore；“热门”按 GitHub API 可用排序展示，不宣称与网页 Trending 一致。

搜索先输入想找的内容，再按需选择仓库、代码、Issue、PR、用户等类型与筛选。高级 GitHub 查询语法仍可直接输入。部分搜索能力需要登录，App 会显示接口返回的限制。

## 阅读文档与代码

仓库概览里点“阅读全文”打开 README。Markdown 文件默认阅读模式，文件操作菜单里可以切换源码。章节链接在当前文档内定位，其他文件链接打开新页面，系统返回回到来源文档。仓库页上方信息可以上滑收起，也可直接拖动头部；完整阅读器保留自己的滑动和选字手势。

文件树按需展开目录；快速打开列出最近文件，并按文件名过滤。在线查找范围为已加载目录和最近文件；保存源码后，可以搜索完整的本机文件索引。

长文本分段显示，每段显示源文件行号；“文件内查找 / 跳行”查找的是完整文件；Markdown 阅读时选择“在源码中查找 / 跳行”会直接打开源码查找窗口。“复制整个文件”与当前段无关，会复制完整原文；长按选字的系统“复制”仅复制当前选区，行号不会混进文本。系统剪贴板拒绝过大的内容时会提示失败，不会偷偷截断。

## 稍后看、Star 与跟踪

| 功能 | 适合做什么 | 去哪里找 |
| --- | --- | --- |
| 稍后看 | 先留着，之后抽空读 | 项目库 |
| GitHub Star | 收藏到 GitHub 账号 | 项目库 → Star |
| App 内跟踪 | 持续看项目公开活动 | 动态 → 跟踪管理 |
| GitHub Watch | GitHub 官方通知订阅 | 仓库官方操作 |
| 离线保存 | 断网也能读本机内容 | 项目库 → 离线与最近阅读 |

App 内跟踪与 GitHub Watch 的用途和数据分别管理。项目库优先显示稍后看，再提供我的仓库等入口；主页更关注个人资料和置顶项目。

## 离线阅读

在仓库“保存到 App”中选择“离线保存资料 / 源码”，勾选资料、源码或两者。完成后从“项目库 → 离线与最近阅读”进入。

资料包含仓库简介、语言和 README；源码是固定提交的文件快照。不同选择独立保存，断网阅读以实际已保存内容为准。界面上的“离线 / 缓存”标记可点开看保存时间。

- 临时缓存只在部分请求失败时回退，容量有限；需要保证断网可读时，请主动离线保存。
- 外部图片不自动离线保存；没有保存的文件链接会提示缺失。
- 快照不含提交历史、子模块和 LFS 实体，不执行项目代码。单个文本读取最多 1 MiB，二进制文件不预览。
- 保存支持取消和重试；进程被结束后不承诺自动续传。删除快照会删除其本机文件。
- 退出或更换凭据会清理私有快照与对应阅读上下文；公开快照保留。

## 下载 Release 文件

打开发布版本，先阅读说明，再选择下载附件或源码归档。系统下载任务可在项目库的“下载”查看、打开或删除；删除失败会保留记录并提示，不会把未删除的文件假装删掉。

公开附件支持 App 内下载；私有附件当前需要打开 GitHub 网页完成认证下载。

“打开文件”会交给手机上的相应应用。打开 APK 时进入系统安装器，由你决定是否允许安装来源和安装；文档或压缩包需要手机上有相应的阅读 / 解压应用。文件缺失或无法打开时会提示原因，文件保存在 `Downloads/RepoRove`。

## 登录与账号

不登录也能读公开项目。登录后可以同步 Star，访问自己的仓库和组织，并处理通知。

### 通过浏览器登录

1. 打开“我的”，点击“通过浏览器登录”。需要访问私有仓库时，再勾选对应选项；默认不开启。
2. 点击“复制授权码并打开 GitHub”，在 GitHub 官方页面粘贴短授权码。
3. 核对应用名称 RepoRove 与授权范围，确认后回到 App，等待自动完成登录。密码只输入在 GitHub 官方网页。
4. 授权码过期或中途取消时，重新发起即可。登录凭据有期限时，App 会在需要访问 GitHub 时续期；授权被撤销或无法续期时，需要重新登录。

GitHub 的公开仓库授权包含写权限，用于 Star 等操作；可选的私有仓库 `repo` 范围更广，包含私有仓库读写。登录页会说明范围。组织可能另外要求管理员批准或 SSO 授权。

### 使用访问令牌登录

展开“使用访问令牌登录”作为备选：

1. 在 GitHub 的 **Settings → Developer settings → Personal access tokens** 创建有期限的令牌。
2. 按需授权要访问的仓库与操作，再粘贴到 RepoRove“我的 → 使用访问令牌登录”。
3. 登录后使用 Star、我的仓库、组织、收件箱等账号功能。若功能返回权限不足，按该功能和 GitHub 的错误信息检查令牌授权。

优先使用最小必要权限；无需为了浏览公开仓库授予全部私有仓库权限。GitHub 的令牌类型支持能力不同，具体以 [官方令牌说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) 为准。令牌只保存在本机加密设置中，不写入日志或上传给项目作者；请勿在 Issues 中粘贴令牌。

当前为单账号设计。可以退出后更换账号；退出不会删除 GitHub 上的 Star 或仓库。

## 外观和习惯

“我的 → 设置”提供清晰 / 纸感、跟随系统 / 浅色 / 深色、阅读字号和列表密度。底部导航可选 1–5 个入口并调整顺序；仓库栏目全仓库共用，少用的可以放到“更多”。

启动时可以询问是否打开剪贴板里的 GitHub 链接，只在 App 前台检查，确认后才跳转；“导航与启动”中可以关闭。

## 反馈与已知边界

当前支持阅读多数 GitHub 对象，但评论提交、PR 审核、重跑 Actions、完整 Discussion 回复和 Projects 看板尚未完整提供；复杂公式和 Mermaid 图形仍以源码显示。AI 翻译已移除。

遇到问题请记录：App 版本、设备 / 系统、复现步骤、预期和实际表现。提交到 [Issues](https://github.com/zurrll/RepoRove/issues)，截图遮住私人信息。后续体验问题会先积累，再集中修复和出包。
