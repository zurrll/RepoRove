# 预览版本发布流程

已授权的改动集中完成并通过验证后，为该版本提供 GitHub Release 和 APK 下载。日常反馈先积累，不因一条反馈重复出包。

1. 更新 `app/build.gradle.kts`：版本代码递增、版本名称明确。同步 App 内 `changelog.json`、根目录 CHANGELOG 与本轮实现记录。
2. 完成涉及的设备回归、单元测试、Debug / Release lint 和 R8 构建。实际安装签名后的 R8 APK，检查线上读取、离线与下载等相关生产流程。
3. 使用本机保留的签名证书；核对包名、版本、签名、zipalign 和 SHA-256。不把密钥、密码或 mapping 写入 Git。当前预览渠道使用同一开发签名，正式渠道签名另行规划。
4. 更新必要的实际 App 截图、使用说明及能力边界。推送源码，等待对应提交的 CI 通过。
5. 给完整源码提交创建版本标签，发布预览 Release，上传 APK、SHA256SUMS、包信息和第三方许可说明。正文写本版具体变化，标注预览状态和验证边界。
6. 核对远端每个资产的大小 / SHA-256，并实际下载最新 APK 校验；确认 README 的下载入口与截图可公开访问。

0.1.0–0.3.0 仅为 Git 建仓前历史 APK 的来源归档，不作为后续打标签的方法。正常新版本必须关联完整且对应的源代码提交，不用新包替代旧包。

当前公开下载位于 [Releases](https://github.com/zurrll/RepoRove/releases)。安装和更新说明见 [使用指南](使用指南.md)，构建命令见 [CONTRIBUTING](../CONTRIBUTING.md)。
